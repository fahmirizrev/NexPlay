- Completion policy:
  Repeat OFF:

  - stop pada final boundary.

  Repeat ONE:
  - replay current item.

  Repeat ALL:
  - wrap pada final boundary;
  - single-item queue replay.

17. COMMAND / POWERSHELL RULES BARU DARI PENGALAMAN PHASE 11
======================================================================

A. Jangan membuat script terlalu kompleks jika command kecil cukup.

B. Windows PowerShell 5.1 memiliki encoding caveat dengan external process.

Masalah yang terjadi:
`git show` output yang mengandung Unicode seperti em dash `—`
tidak selalu menghasilkan string yang identik ketika ditangkap ke variabel
PowerShell.

Akibatnya:
heading yang terlihat benar bisa gagal exact-match.

Rule baru:
untuk memanipulasi local text files:
prefer:
[System.IO.File]::ReadAllText(...)
[System.IO.File]::ReadAllLines(...)

daripada menangkap output `git show` lalu melakukan exact Unicode matching.

Jika perlu restore baseline:
gunakan:
git restore --source=HEAD -- <file>

lalu baca file lokal via .NET.

C. Untuk heading/section matching:
- jika Unicode berpotensi bermasalah, gunakan stable ASCII prefix,
  contoh:
  "# 18. Phase 11"
  bukan exact whole heading yang mengandung em dash.
- line-based matching lebih aman daripada giant multiline regex.

D. `$ErrorActionPreference = "Stop"` TIDAK otomatis menghentikan script
ketika native executable seperti `git` return non-zero.

Contoh masalah yang terjadi:
git diff --cached --check
menemukan trailing whitespace,
tetapi git commit tetap dijalankan.

Untuk critical Git command:
selalu cek:

git diff --cached --check
if ($LASTEXITCODE -ne 0) {
    throw "git diff --cached --check failed."
}

Hal sama jika diperlukan untuk:
- git commit
- git push
- gradlew
- adb command kritis

E. LF → CRLF warning:
warning seperti:

LF will be replaced by CRLF the next time Git touches it

bukan whitespace error.

Jika `git diff --check` hanya mengeluarkan LF/CRLF warning:
anggap tidak ada whitespace violation.

F. PowerShell continuation:
jika terminal masuk prompt `>>` tidak sesuai harapan:
Ctrl+C sekali lalu ulangi command.

G. Jangan menaruh literal nested triple-backtick secara ceroboh di
PowerShell here-string yang dikirim melalui chat.
Jika perlu markdown fences:
$fence = [string]::new([char]96, 3)

Sebelum commit:
1. verification relevan harus sudah pass;
2. docs sinkron;
3. git diff --check;
4. git add;
5. git diff --cached --check;
6. CHECK $LASTEXITCODE;
7. review git status;
8. commit;
9. push;
10. final git status;
11. git log.

Jangan commit:
patches/output/

Jangan amend/force-push hanya untuk cleanup kecil yang sudah ter-push jika
simple follow-up commit lebih aman.

Contoh PHASE 11:
commit utama:
973d521 feat(player): add native audio player

cleanup:
c1c430a chore: clean Sora license whitespace

Final:
main == origin/main
working tree clean.
