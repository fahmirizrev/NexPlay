4. ARCHITECTURE CONTRACT YANG WAJIB DIPERTAHANKAN
==================================================

QUEUE ENGINE

QueueEngine adalah authoritative owner untuk:

- queue items
- current index
- current item
- shuffle
- repeat
- playback context
- next / previous policy
- queue mutation
- completion policy

QueueEngine:

- pure domain;
- tidak mengenal Compose;
- tidak mengenal Media3;
- tidak memiliki ExoPlayer;
- tidak membaca MediaStore;
- tidak memiliki MediaSession;
- tidak memiliki persistence.

Current item selalu diturunkan dari:
items + currentIndex.

Playback context yang tersedia:

- FolderContext
- PlaylistContext
- SearchContext
- PlayHubContext
- SingleItemContext

==================================================

PLAYBACK ENGINE

PlaybackEngine adalah authoritative owner untuk:

- satu ExoPlayer;
- prepare;
- play;
- pause;
- stop;
- seek;
- runtime playback state;
- position;
- duration;
- buffering;
- playback error;
- lifecycle ExoPlayer.

Tidak boleh:

- memiliki queue sendiri;
- menentukan next / previous sendiri;
- mengetahui repeat policy;
- menjadi source of truth untuk queue.

Satu ExoPlayer dipakai untuk:
- audio;
- video;
- MediaSession;
- background playback;
- UI player.

==================================================

QUEUE + PLAYBACK COORDINATOR

QueuePlaybackCoordinator adalah satu-satunya explicit integration boundary antara:

QueueEngine
dan
PlaybackEngine.

Flow:

Queue chooses media
→ QueuePlaybackCoordinator
→ PlaybackEngine
→ Same ExoPlayer

Ketika playback ENDED:

PlaybackEngine
→ QueuePlaybackCoordinator
→ validate media masih current
→ QueueEngine menentukan completion action
→ STOP / REPLAY_CURRENT / ADVANCED

Stale ENDED callback dari source lama wajib diabaikan.

16. CHILD LOCK — FINAL DESIGN
==================================================

Child Lock sekarang bukan sekadar lock Compose controls.

Flow:

Video Player
→ ⋮
→ Child lock

Child Lock melakukan:

- NexPlay controls hidden;
- tap blocked;
- double tap blocked;
- seek blocked;
- transport controls blocked;
- Android Back consumed;
- status/system bar handling diketatkan;
- Android `startLockTask()` dipanggil;
- Screen Pinning Android digunakan;
- video tetap terus playing.

Penting:

Ini BUKAN true Device Owner / kiosk mode.

Screen Pinning:
- cocok untuk aplikasi consumer biasa;
- tidak memerlukan Device Owner;
- masih mengikuti Android/OEM escape policy.

True exam/kiosk behavior yang benar-benar dapat menonaktifkan:
- notification shade;
- Home;
- Recents;
- System UI;
memerlukan Device Owner / DPC / managed dedicated device.

Keputusan terbaru:

JANGAN mengubah NexPlay menjadi Device Owner hanya untuk Child Lock.

True kiosk mode = out of scope.

21. CODEC COMPATIBILITY
==================================================

Discussion terbaru:

Native Kotlin + Media3 tidak otomatis menyelesaikan semua masalah codec Flutter.

Current:

- minSdk = 23
- targetSdk = 37
- Media3 = 1.11.0

Media3 / ExoPlayer masih menggunakan decoder Android/platform MediaCodec secara default.

Compatibility bergantung pada:

- codec;
- profile;
- level;
- container;
- resolution;
- bitrate;
- bit depth;
- hardware decoder;
- OEM implementation.

Baseline paling aman:

VIDEO
- MP4
- H.264 AVC

AUDIO
- AAC-LC
- MP3
- FLAC
- WAV

HEVC / VP9:
lebih device-dependent.

AV1:
jangan dianggap old-device baseline.

Decision:

JANGAN menambahkan FFmpeg/software decoder sekarang.

Reason:
- binary size;
- build complexity;
- maintenance;
- CPU;
- battery;
- belum terbukti dibutuhkan.

Codec Compatibility Audit tetap:

PHASE 21 — Codec Compatibility dan Old Device Hardening.

PHASE 13 tidak diblokir oleh broad codec matrix.
