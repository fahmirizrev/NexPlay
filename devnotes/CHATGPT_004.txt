======================================================================
14. SHUFFLE CONTRACT
======================================================================

Flutter reference yang dipakai terutama AudioPlayerController karena
implementasi shuffle-nya lebih lengkap daripada video controller.

Behavior native Queue Engine:

Saat shuffle ON:
- current item dipertahankan;
- current item menjadi index 0;
- item lain diacak;
- original order disimpan.

Saat shuffle OFF:
- original queue order dikembalikan jika original snapshot masih valid;
- current item dicari kembali dalam original queue;
- currentIndex disesuaikan.

Jika queue dimodifikasi ketika shuffle aktif:
- stale pre-shuffle restore snapshot dibatalkan;
- engine tidak mencoba mengembalikan urutan lama yang sudah tidak valid.

Identity media mengikuti Flutter-style matching:
- same id
  ATAU
- same uri.


======================================================================
15. QUEUE ENGINE OPERATIONS
======================================================================

Operations yang sudah diimplementasikan:

- setQueue()
- playAt()
- next()
- previous()
- append()
- insertNext()
- remove()
- move()
- clear()
- toggleShuffle()
- setRepeat()

Behavior penting:

setQueue():
- queue kosong → queue/current/context dibersihkan;
- index di-clamp ke valid range;
- jika shuffle mode sudah aktif, selected item tetap menjadi current item.

playAt():
- hanya mengubah currentIndex jika index valid.

append():
- menambah item di akhir.
- jika sebelumnya queue kosong:
  currentIndex = 0
  playbackContext = SingleItemContext

insertNext():
- insert setelah current item.
- jika queue kosong menjadi single-item queue.

remove():
- current item dipertahankan bila masih tersedia.
- jika current item sendiri dihapus:
  pilih item berikutnya jika ada;
  jika tidak, pilih item sebelumnya.
- jika queue menjadi kosong:
  currentIndex = -1
  currentItem = null
  playbackContext = null

move():
- reorder queue.
- current item tetap current walaupun index berubah.

clear():
- items kosong
- currentIndex = -1
- playbackContext = null
- shuffle/repeat preference tetap dipertahankan.

20. RULE MARKDOWN DOCS
======================================================================

Masalah:
Markdown code fence di dalam response ChatGPT dapat merusak rendering chat,
terutama ketika command PowerShell sendiri mengandung literal triple backtick.

Keputusan:

Semua perubahan file .md dilakukan melalui PowerShell command.

Jangan memberikan patch Markdown biasa dalam chat.

Untuk code fence Markdown:
jangan tulis literal tiga backtick di dalam PowerShell here-string yang
dibungkus code block ChatGPT.

Gunakan:

$fence = [string]::new([char]96, 3)

Lalu generate fence secara programatis.

Untuk file Markdown:
- gunakan ReadAllText / WriteAllText;
- UTF-8 no BOM;
- normalize LF ketika melakukan exact replace;
- gunakan replacement yang narrow dan deterministic;
- kalau section besar, replace section berdasarkan heading/regex;
- setelahnya selalu review dengan git diff.

Warning seperti:

LF will be replaced by CRLF

bukan kegagalan git diff --check.
Itu line-ending warning Windows/Git.
